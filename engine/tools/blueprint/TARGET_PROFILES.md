# Project target profiles (initial implementation)

New and legacy native projects default to original Xbox, 64 MiB unified RAM, 640 x 480. Build & Package contains platform, Xbox RAM and resolution selectors. Windows, Linux, macOS, Xbox 360 and UWP (Xbox One/Series Developer Mode and Windows) are selectable metadata, not claims of platform feature parity. Xbox 360 and UWP console hardware are not certified.

Original Xbox reference: 733 MHz CPU, 64 MiB unified DDR, nominal 200 MHz clock / 400 MT/s, 128-bit bus, 6.4 GB/s theoretical peak. 128 MiB and experimental 256 MiB profiles do not imply stock compatibility or a known memory clock. The 256 MiB profile warns about possible reduced bandwidth; actual clocks depend on the modification.

Widget preview now uses the saved target resolution (640x480, 720x480 anamorphic 16:9, 1280x720 or 1920x1080). The latter is an authoring size for OG Xbox 1080i, not 1080p capability. The anamorphic canvas displays at the intended aspect with matching pointer transforms. On a 1920x1080 canvas the resolution dropdown offers three independently toggleable, centered lower-resolution footprint guides. The 720x480 anamorphic footprint is 853 1/3 x 480 in square display pixels. These are comparison overlays, not responsive reflow previews. Linked widget pages compile with the saved authoring size; full-screen Ui::draw preserves the centered aspect and inverse mouse coordinates. Explicit rectangular draws remain caller-controlled. Resolution selection does not configure the runtime video mode yet. Exact 720x480 output for the anamorphic target assumes display-side stretching; actual TV mode must be verified.

The build manager compiles and validates AngelScript and displays an illustrative surface cost (two 32-bit colour buffers plus one 32-bit depth buffer, excluding pitch, MSAA, tiling, runtime and assets). A successful script check never implies hardware fit. The desktop profiler uses the selected RAM reference, not console measurements. A target-aware asset dependency/cooked-size and capability audit, per-scene resource budgets, device deployment, real-console telemetry, runtime video configuration, and native hardware verification are follow-up work. No CPU/GPU/FPS predictions are made.

The explicit Check runtime integrity command additionally reads project-owned media, totals source file bytes, and reports unresolved directly authored asset: references on supported loader nodes. Global/computed references and shared Behaviour scopes remain unverified. Disk bytes are not resident memory, and unresolved references are advisory (cooked alternatives and dynamic execution may change what is required). Scene placement shows the number of statically authored placements and the selected memory budget, not a complete entity count. Widget content thumbnails use the same target aspect and canvas as the designer.
